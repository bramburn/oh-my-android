## 4. Golden rules

1. **Docs first.** Behaviour change ⇒ update the nearest `AGENTS.md` + the relevant
   `docs/architecture/*.md` in the **same commit**.
2. **Cite evidence.** Every non-obvious claim gets `path/to/file.ext:LINE-LINE`. Never invent a file,
   flag, command or behaviour. If you did not read it, say so; if you did not run it, write `UNVERIFIED`.
3. **`Sources/**` is read-only.** It is the reference implementation. Do not edit, move or delete it.
   Do not delete or disable `.github/workflows/build.yml` (macOS CI stays green).
4. **No MCP server on Windows.** Do not port `Sources/MCP/**`, do not add `.mcpb`/registry metadata work.
5. **No live screen mirroring.** Snapshots + `input` only (`docs/windows-port/02-mirroring-options.md`).
6. **No new dependency without an ADR** in `docs/adr/`. No framework swap without a new ADR.
7. **All adb access through one choke point** — the Rust `AdbProcessRunner`/`AdbClient`. UI code never
   spawns a process.
8. **The UI never blocks on adb.** Every device call is async, cancellable, and has an explicit error path.
9. **No telemetry, ever.** No analytics, no crash upload, no network call except an opt-out update check.
9b. **Bytes never ride on JSON IPC.** `Channel<Vec<u8>>` JSON-encodes bytes (verified on docs.rs 2.12.5);
   use `Response`/`InvokeResponseBody` for one-shots, disk paths for screenshots, loopback HTTP for video.
10. **Preserve upstream attribution.** `LICENSE` unchanged; `NOTICE.md` current.
11. **Do not reuse upstream identity**: not the name "Oh My Android", not the icon, not
    `se.royan.ohmyandroid`, not the Sparkle feed URL or EdDSA key (`docs/legal.md`).
12. **Never squash upstream history**, never force-push `main`/`upstream-main`.
13. **Device data never leaves the machine**; redact serials and absolute host paths in anything shared.
14. **Quote everything that reaches `adb shell`** (`shellQuoted`-equivalent; `Sources/Core/Support.swift:14`).
15. **Mark unexecuted commands `UNVERIFIED`.** No exceptions for "obvious" commands.

## 6. Architecture invariants (testable)

1. There is exactly **one** place in the Windows app that spawns a process (`AdbProcessRunner`).
2. Every spawned process is created without a visible console window and belongs to a Job Object so it
   dies with the app.
3. Every adb invocation passes an explicit device serial (`-s <serial>`); no implicit-device command
   exists in the codebase.
4. The device list updates without user action (event-driven or bounded polling ≤2 s).
5. The panel renders an explicit state for each of: adb missing, adb failing, emulator starting, device
   booting, unauthorized, offline, no device, ready. No state shows stale data from another device.
6. No feature read costs more than one adb process per refresh (batched shell).
7. Cancelling a UI action terminates its child process within 1 s.
8. No network request is made unless the user opted into update checks.
9. Closing the app closes every child process and every open device socket.
10. No `Command::new` outside `crates/adbkit`/`src-tauri/src/win`; no adb literal in `src/**`
    (CI `rg` guards, `docs/windows-port/17-testing-strategy.md` §8).
11. Device commands always carry an explicit serial; the only `Option<serial>` cases are host-level commands.

## 7. ADB safety rules

**Read-only allowlist** (safe in scripts/tests): `devices -l`, `get-state`, `shell getprop <name>`,
`shell pm list packages`, `shell wm size`, `shell wm density`, `exec-out screencap -p`,
`shell dumpsys …` (read-only dumps), `logcat -d`.

**Requires explicit human approval**: `install`, `uninstall`, `push`/`pull`, `rm`, `pm clear`,
`pm reset-permissions`, `settings put`, `settings delete`, `setprop`, `am force-stop`, `svc wifi|data`,
`cmd connectivity`, `wm density <n>`, `emu …`, `reboot`, `root`, `remount`, `kill-server`,
`start-server`.

Also: always `-s <serial>`; never assume a single device; never run adb in a unit test (integration only,
behind a flag + serial env var); never add root features.

## 8. Data safety & privacy

No device data leaves the machine. Only `debuggable=true` apps may be read (via `run-as`), read-only.
Redact serials (use last 4 chars) and absolute host paths in shared output. Sanitize device-supplied
filenames before using them as local paths (`docs/architecture/12-risks-and-tech-debt.md` R12).

## 9. Conventions

- **Rust**: `snake_case`, `Result<T, AppError>` where `AppError` implements `std::error::Error`; no
  `unwrap()`/`expect()` outside tests and `main`; all blocking work on `spawn_blocking`/tokio tasks.
- **TypeScript**: `camelCase`, strict mode, no `any`, no class components, state in one store module.
- **Serialization across the IPC boundary**: typed structs, never ad-hoc JSON strings.
- **Errors** are user-readable sentences, not error enums, at the UI boundary.
- **Files**: one responsibility per module; mirrors of upstream file names are encouraged so the
  reference stays easy to compare (`adb_client.rs` ↔ `ADBClient.swift`).
- **Swift (reference only)**: tabs indent 4, Swift 6 strict concurrency, zero warnings.

## 10. Testing expectations

Any change to a parser or a device command needs a fixture test with a recorded transcript. The MCP
protocol test does not exist on Windows (no MCP server) — do not port it. See
`docs/windows-port/06-testing-strategy.md`. Fake-adb fixtures live in `src-tauri/tests/fixtures/`.
Real-device tests require `OMA_INTEGRATION=1` and `OMA_SERIAL=<serial>`; they must skip otherwise.

## 12. Windows-port guardrails

- Target: **Tauri v2** (Rust + WebView2 + TypeScript UI), **installer** (MSI/NSIS), x64 first.
- No cross-platform abstraction leaks: Windows-only code, no `cfg(unix)` fallbacks "just in case".
- Spawn with `CREATE_NO_WINDOW`; assign to a Job Object; kill on app exit.
- `adb shell` output is UTF-8 but may contain OEM-codepage bytes — decode lossily and never panic.
- Device shell output contains `\r\n`; trim `\r` before parsing or comparing.
- Quote every path (spaces are normal: `C:\Program Files (x86)\…`). Never build a command string for
  `adb shell` without single-quoting user text.
- Video is **not** on IPC and **not** on a custom protocol (its responder body is buffered,
  `http::Response<Vec<u8>>`); only loopback HTTP with a per-session token.
- Never present a recalled Tauri v1 API as v2 fact: the verification table is
  `docs/windows-port/10-version-pin.md` §4, and `register_asynchronous_uri_scheme_protocol`,
  `additional_browser_args`, `bundle.resources` vs `externalBin`, and `WebviewInstallMode` are already
  checked there.
- Do not implement docking to the emulator window in MVP (`docs/feature-matrix.md`, tier P2).

## 13. Recipes

**Add a device action:** 1) add a `Feature` variant in the Rust feature catalog, 2) add its read command
(one shell string) and parse function with a fixture test, 3) expose it through the single IPC command
surface, 4) render it in the UI grid, 5) update `docs/feature-matrix.md` + the nearest `AGENTS.md`.

**Add a screen:** 1) state it in the panel-state enum if it is a device condition, 2) add the view,
3) add a UI smoke test, 4) add a "Windows rethink" line to `docs/architecture/08-ui-ux-map.md`.

**Add an adb command:** 1) add it to `docs/architecture/06-adb-integration.md` (row: args, call site,
quoting, mode, parsing, exit codes, timeout, frequency, failure modes), 2) then implement it.

## 14. Doc-drift rule

Behaviour change ⇒ same-commit update of: nearest `AGENTS.md`, the affected `docs/architecture/*.md`,
`docs/feature-matrix.md` when a tier/feasibility moves, and `NOTICE.md` when a source file changes for
the first time.

## 15. Gotchas

- The upstream app **bundles no adb**; licence forbids redistribution. Bundling for Windows is an
  unresolved licensing decision (`docs/open-questions.md` #3).
- `agents.access` defaults to **full control** upstream — do not copy that default.
- `DebugPropertyToggleFeature` uses a magic `service call activity 1599295570`; stability across Android
  versions is `UNVERIFIED`.
- Emulator console splits arguments on spaces (`Sources/Features/CaptureFeatures.swift:52-58`).
- `docs/upstream/**` links are broken by relocation on purpose — do not "fix" them.
- Open questions: `docs/open-questions.md`; risk register: `docs/windows-port/19-risk-register.md`.
- `bundle.externalBin` needs a `-x86_64-pc-windows-msvc.exe` suffix and cannot carry `AdbWinApi.dll`;
  adb must ship as `bundle.resources` if it ships at all.
- Capabilities gate **plugin** commands only — app-defined `#[tauri::command]`s must validate their own
  preconditions server-side.
- `tauri dev` and `tauri build` produce different origins; CSP `connect-src` must cover both.
