# 21 — MVP log (Windows scaffold)

Living record for the `feat/win-mvp-tauri` branch. Newest section last.

## 1. Scope

Three commands — `list_devices`, `adb_start`, `adb_stop` — a monochrome device list, and an NSIS
installer. Everything else is out (`docs/adr/ADR-0007-win-mvp-scaffold.md`).

| # | Override | Status |
|---|---|---|
| **O1** | Device list updates on explicit **Refresh** only. Invariant #4 (event-driven hotplug, `Sources/Core/Android/DeviceTracker.swift:96-118`) is **deferred**. | Active for this MVP |
| **O2** | **Start/Stop targets the adb server** (`adb start-server` / `adb kill-server`), not emulators or devices. `kill-server` is on the human-approval list (`AGENTS.md` §7); the button + `confirm()` dialog *is* the approval. Never automatic, never in a test. | Active for this MVP |

### Threat/correctness notes from implementation

- `AppError::from_output` puts adb's stderr in `message`; a test asserts the *spawn* path does not leak host
  paths. adb's own stderr is user-facing by nature (e.g. `INSTALL_FAILED_*`) and contains no host paths.
- Commands take no serial: the MVP has one implicit device list and no mutating per-device command, so
  invariant #11 ("always `-s`") is vacuous here. It becomes mandatory in the first milestone that adds a
  per-device action.
- `window.confirm` is used for Stop. WebView2 renders its own modal; if a future WebView2 version suppresses
  it, replace with an in-app confirm dialog (`UNVERIFIED` — only exercised by recipe, not clicked).

## 4. Persistence and migration rule (encoded now, used later)

- **There is no database and no migration in this MVP.** Upstream persists only preferences
  (`docs/architecture/04-data-and-state.md`); this MVP persists **nothing** — the SDK path is re-located on
  every command by `adbkit::sdk::locate`.
- Any future persisted store is JSON with `"schemaVersion": 1`. Bump on a breaking shape change.
- Migration scripts are committed as files but **executed only in the main repo checkout, only after the
  merge, only with human approval**. Never in the worktree, never by the agent.
- Merge-back (run by the human, not the agent):

```powershell
cd C:\dev\oh-my-android
git merge --no-ff feat/win-mvp-tauri -m "merge: win MVP tauri scaffold"
# migrations: none for this MVP. If a future merge adds one, run it HERE, now, not before.
git worktree remove C:\dev\worktrees_tmp\oma-win-mvp
git branch -d feat/win-mvp-tauri   # optional, after verification
```

## 7. UNVERIFIED items

- **No device was ever connected.** `adb devices -l` returned an empty list on this machine, so the
  `empty` UI state is the only list state exercised for real; the `ready` list state is exercised only by
  fixtures and by `cargo test`.
- The UI was **not clicked** by a human or a driver: `Refresh`/`Start`/`Stop` were verified by reading the
  code paths and by running the same adb commands from the shell, not by pressing the buttons. No WebDriver
  (`tauri-driver`/msedgedriver) was set up.
- `window.confirm` behaviour inside WebView2 (assumed to work; not exercised).
- NSIS install on a **clean** machine (the installer was built, never run), SmartScreen, per-user uninstall
  leftovers, `downloadBootstrapper` offline behaviour.
- Windows 10 22H2, 200 % DPI, multiple monitors.
- `.github/workflows/windows.yml` has not run on GitHub (nothing was pushed).
- `npm audit`'s 2 low-severity dev-dependency advisories were not triaged.

## 9. Follow-ups created by this MVP

1. **Daemon lifetime (D5).** Decide whether the adb server should survive app exit like upstream, and if so
   spawn daemon-starting commands with `CREATE_BREAKAWAY_FROM_JOB` / a separate non-job runner. Needed before
   logcat/`adb shell` streams land, because those need tree-kill *and* daemon survival.
2. **Verify the UI interactively** and add `tauri-driver` or a Playwright harness against `devUrl`
   (timeboxed; see `17-testing-strategy.md` §5).
3. `app.css` uses `code` and `pre` styling? No — deliberately unstyled; add only if a screen needs it.
4. Replace `window.confirm` with an in-app dialog when Settings lands (native dialogs need a capability
   decision).
