# Assumptions

Every entry: statement, confidence, blast radius, how to falsify.

| # | Assumption | Confidence | Blast radius if wrong | Falsify with |
|---|---|---|---|---|
| A1 | The app is developed and shipped **Apple-silicon only**. README says "macOS 26 Tahoe+ · Apple silicon"; `project.yml` sets no `ARCHS`/`ONLY_ACTIVE_ARCH`, so a universal build is *possible* but not asserted anywhere. | Medium | Low: affects only "can x86 Macs run it". Irrelevant to a Windows port. | `codesign -d --arch` on a release zip, or check GitHub release asset names. |
| A2 | `deploymentTarget: macOS 26.0` is a hard requirement because the UI uses APIs newer than macOS 15 — `glassEffect` (`Sources/UI/PanelRootView.swift:20`), `WindowDragGesture` (`:22`), `SMAppService` is older. Nothing in the code gates them with `if #available`. | High | Medium: a port must re-implement the glass look anyway, so this only matters for "can we reuse the SwiftUI views on older macOS". | Build with `MACOSX_DEPLOYMENT_TARGET=15.0` and read the errors. |
| A3 | Feature state is **never** persisted for the device; every toggle is written straight to the device (`settings put`, `cmd uimode`, `wm density`). The only local persisted state is UI preference (`panel.pinned`, `panel.dockToEmulator`, `device.lastSerial`, `agents.access`, `recording.quality`, `sdk.customRoot`, `settings.tab`). | High | Medium: a Windows port must not add a settings mirror it does not need. | `rg "UserDefaults\|CFPreferences"` — 7 keys, all UI/policy, none device state. |
| A4 | MCP screenshots are downscaled so that 1 px = 1 dp. Claimed in `Sources/MCP/Server/Catalog.swift:11-12` and `mcpb/manifest.json`; the code lives in `Sources/Core/Imaging/ImageScaler.swift`, which was **not read**. | Medium | Low: affects token cost and coordinate mapping, not architecture. | Read `ImageScaler.swift`; call `screenshot` on a 420 dpi device and compare pixel size to `wm size`. |
| A5 | `adb` is **never** bundled; the app hard-requires an SDK the user already has (`Sources/Core/Android/AndroidSDK.swift:3-6`, `:13-32`). Google's SDK licence is the stated reason. | High | High for a Windows port: bundling `platform-tools` changes licensing and the first-run story. | Read Google's `platform-tools` redistribution terms; compare with how Android Studio ships it. |
| A6 | There is **no** background poller for device state; hotplug is push-only via `host:track-devices`, plus a 4 s recovery loop that only runs while nothing is ready (`Sources/State/DeviceStore.swift:75-90`). | High | Medium: a port must reproduce both mechanisms or the panel goes stale on boot-complete. | Run the app, unplug/replug, watch `adb` invocations (`fs_usage`/`dtrace`), or read the code paths. |
| A7 | Every `adb` call is one-shot. Nothing is a long-lived stream (no `logcat` follow, no `track-devices` other than the tracking socket). | High | Medium: the Windows architecture does not need stream plumbing for the MVP. | `rg "logcat"` → only `-d` (`Sources/MCP/Tools/AppTools.swift:135`). |
| A8 | Command execution is **safe from device-output attacks** in the sense that stdout is only displayed/parsed, never re-executed. The only place device output influences a later command is logcat filtering, which is quoted (`Sources/MCP/Tools/AppTools.swift:141`). | Medium | High if wrong: would be a command-injection class bug. | Audit every `try? await shell(` whose argument is derived from a previous `shell` result. |
| A9 | The MCP server reads the app's access policy from the same preferences domain, so it works **without** the app running (`Sources/Core/AgentAccess.swift:35-50`), and defaults to **full control** when the app was never installed (`Sources/Core/AgentAccess.swift:44`, `mcpb/manifest.json` long_description). | High | High: a Windows port must decide the default access level explicitly. This default is a security decision, not an accident. | Uninstall the app, run the server, call `manage_app`. |
| A10 | `mcpb`, `server.json`, `.claude-plugin` and `glama.json` are distribution metadata only; no runtime code reads them. | High | Low. | `rg "server.json\|glama"`. |
| A11 | The project has **no unit tests**, so any port starts from near-zero test coverage. The Python script tests the MCP protocol only (`Scripts/test-mcp.py:1-8`). | High | High: a port's test strategy must be built, not migrated. | `rg -l "XCTest\|Testing" Sources` → 0 hits. |
| A12 | The upstream default branch is `main` and is the release branch (tags `v0.3.0`…`v0.4.6` on it). | High | Low. | `git branch -r --contains v0.4.6`. |
